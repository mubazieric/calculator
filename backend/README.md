# IWAT AI Plus backend — deployment guide

This server requires Node 22+, PostgreSQL, a Google Play Developer API service account authorized in Play Console, and an AI provider key. It does **not** run inside the Android APK. No payment or cloud AI feature can be used until a working public HTTPS service and Play subscription exist.

1. Create a monthly auto-renewing subscription in Play Console with product ID `iwat_ai_plus`, a monthly base plan, proposed price **US $7.99/month** (localized by Play), and no trial initially. Enroll the app in internal testing and add license testers. Do not charge production customers before end-to-end tests and a published privacy notice.
2. Create a dedicated Google Cloud service account, grant only the necessary Play Console financial/order access for subscription lookups and acknowledgement, and enable the Google Play Developer API. Store credentials in a secret manager, never in Git or the APK.
3. Provision PostgreSQL, apply `schema.sql` with `psql "$DATABASE_URL" -f schema.sql`, and set variables from `.env.example` securely. `DATABASE_SSL=true` is supported for a verified server certificate; use private networking for the database. Run `npm install`, `npm test` and `npm start` behind a public HTTPS reverse proxy with request timeouts, body size limits, authentication monitoring and infrastructure rate limits.
4. Build the Android app with `-PIWAT_AI_SERVER_URL=https://your-api.example` (this exposes only the public endpoint, not a key). Install from a Play testing track to exercise Play Billing. Without this property, the purchase and AI photo buttons are disabled. Verify pending, active, canceled-but-unexpired, expired and refunded subscriptions; verify the monthly cap and restoration after reinstall.
5. Monitor provider token consumption (`ai_requests.input_tokens`, `output_tokens`), provider spend alerts and errors. Consider Play Integrity verification, user-account binding, IP/device abuse controls, rate limits, RTDN subscription lifecycle events, and token-rotation/linked-purchase handling before wide release. Purchase tokens act as bearer credentials: keep them confidential and do not log them. Deploy an external data retention/cleanup policy for old usage rows and results. `GET /health` is for health checks only.

Endpoints: `POST /v1/entitlement` with `{purchaseToken}`; `POST /v1/solve-photo` with `{purchaseToken, requestId (UUID), imageBase64 (JPEG)}`. Both re-check subscription status with the Play API. The latter atomically reserves a usage slot (50 per UTC calendar month), returns a cached result for repeat IDs, and refunds failed requests. Client-side purchase states do not unlock AI access. A temporary failed request can occupy a slot for up to 10 minutes; retry with a new request ID after timeout. The server may still incur provider costs for failed/ambiguous requests; include this in the pricing reserve.

**Pricing sensitivity (not guaranteed profit):** At $7.99/month and an *assumed* 15% Play fee, net receipts are ~$6.79 before taxes. If all 50 included analyses cost $0.05 in AI API usage each, that leaves ~$4.29 to cover hosting, support, refunds, taxes and profit; at $0.10 each it leaves ~$1.79. If your average exceeds $0.05, lower the cap or raise price before launch. Set per-account and global provider spending alerts. Actual Play fees, regional prices, VAT and token costs vary. Do not promise unlimited use.
